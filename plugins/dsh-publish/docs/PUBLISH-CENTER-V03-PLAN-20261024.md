# 发布中心 v0.3 方案：平台优先 · 独立可视

> 项目: 老王工作台发布插件（dsh-publish）
> 日期: 2026-10-24（同日修订：公众号 / X 明确不做；新增批次 3 登录编排）
> 状态: 批次 1（平台优先重构）、批次 2（小红书数据回采）已合入 main；批次 3（登录编排）为老王 2026-10-24 复审后新增的最高优先级；视频号受控验收顺延为批次 4
> 前置: v0.2 已合入 main（PR #1），发布中心四标签已上线
> 需求来源: 老王 2026-10-24 口头需求

## 0A. 复审结论（2026-10-24 第二次复审：登录能力缺失，成立）

老王复审指出：**每个平台都显示登录态，但插件没有任何登录入口、登录能力、登录功能**——账号只能手填别名，登录要自己开终端跑上游命令。审核确认这是功能缺失：账号闭环是「绑定 → 登录 → 发布 → 核验」，前两批只做了展示层，登录这一环整个缺失，登录态展示因此空转。

**上游能力核验（v2.5.5 / 3847fff 一手资料），两个引擎都能补上这一环：**

| 引擎 | 登录能力 | 插件编排方式 |
|---|---|---|
| xiaohongshu-mcp | `GET /api/v1/login/qrcode` 返回 base64 二维码图 + `timeout`（秒）+ `is_logged_in`；轮询 `/api/v1/login/status` 判断扫码成功 | 页面内完整扫码登录：显示二维码 → 轮询状态 → 过期自动重取 → 成功刷新。纯 HTTP，服务级登录（多别名共享服务登录态，与既有文档一致） |
| social-auto-upload | 每个平台都有 `sau <platform> login --account <name>`；默认 headless 也会生成临时二维码图，`--headed` 弹出可见浏览器扫码；一个别名一份 cookie 文件；仅抖音短信验证需 verify_code.txt 或交互终端 | 后台任务编排：点「去登录」→ 以 `--headed` 启动登录任务（jobs 托管、可取消）→ 用户在弹出的浏览器里扫码 → 任务结束自动回查登录态。桌面版就在用户本机，弹浏览器即正确交互 |

**边界**：扫码永远由人完成，插件做的是把「开终端敲命令」产品化，不做自动登录、不碰风控。小红书服务级登录（一个服务一份 cookie）沿用既有约束，多账号 worker 另立项。

## 0. 已确认决策（2026-10-24）

1. **公众号、X 不做**：上游两个引擎都没有这两个通道，v0.3 不注册占位、不放置灰空卡，从默认主页与能力表登记中完全移除；将来要接入时另立项评估（记录于第 9 节批次 3）。
2. **默认主页 = 有引擎的 3 个平台**：抖音、小红书、视频号（按老王给的顺序）；其余平台收进「更多平台」。
3. **发布表单放进平台详情**（老王采纳推荐项）：发布一律从平台进入，表单字段随平台形态变化。

## 1. 需求原文与解读

1. 默认平台：**抖音、小红书、视频号**；其余平台收进「更多平台」，用户点击后才添加到主页。
2. 每个平台的内容形式不同（图文 / 文章 / 视频），**每个平台的发布界面独立、按其内容形态清晰呈现**。
3. **主页上每个平台的模块可以随意拖动、重新排序**，顺序记住。
4. **不设假按键、不放多余按键**：每个看得见的按钮都必须对应一个真实功能；保留 v0.2 全部既有功能，设计做减法。

对应到信息架构，本版把 v0.2 的「功能优先」（四个并列标签）改为「**平台优先**」：平台是主页的一等公民，发布、记录、日历、数据全部先按平台切分，全局视图只有总览心跳和全局日历两处。

## 2. 现状核验：默认 3 平台的真实能力（先说实话）

能力真值来自 `src/platforms.ts` 与两个上游引擎，以下是截至今天的核实结果：

| 平台 | 平台 id | 引擎 | 内容形态 | 定时 | 现状 |
|---|---|---|---|---|---|
| 抖音 | `douyin` | sau | 视频、图文 | ✅ sau `--schedule` | ✅ 可用 |
| 小红书 | `xiaohongshu` | xiaohongshu-mcp | 图文、视频 | ✅ 上游 1 小时~14 天 | ✅ 可用（唯一支持数据回采） |
| 视频号 | `tencent` | sau `tencent` | 仅视频 | ✅ sau | ⚠️ 已登记未受控验收：能力来自上游 README 能力表，我们尚未真实发布验收过 |

「更多平台」面板里的平台全部有引擎背书（快手、B站、知乎、雪球、大鱼号、微博、虎扑、百家号、支付宝生活号、YouTube），其中 B站仍带上游限制（`--tid` 未接）。**公众号、X 无引擎背书，本版不做**（见第 0 节决策 1）。

## 3. 信息架构

```text
发布中心
├─ 总览（默认首页）
│   ├─ 全局心跳条：今日已发 / 本月已发 / 待核实 / 已排期 / 引擎状态
│   ├─ 我的平台：按用户排序的可拖拽卡片网格（默认 5 张）
│   ├─ 发布日历（全局 · 按平台着色 · 点日期过滤）
│   └─ 「+ 更多平台」入口卡 → 展开面板
├─ 平台详情（点卡片进入，带「返回总览」）
│   ├─ 平台头：图标 / 名称 / 账号切换 / 登录态 / 状态操作
│   ├─ 新建发布（只显示该平台支持的内容形态与字段）
│   ├─ 发布记录（只看该平台）
│   ├─ 本平台日历
│   └─ 数据中心（仅小红书；其他平台显示「上游无数据接口」）
├─ 账号（全局账号别名管理，保留 v0.2 能力）
└─ 设置（v0.2 全部设置项不变）
```

与 v0.2 的差异：全局「新建发布」标签取消——发布一律从平台进入，表单天然只出该平台的形态；「发布记录」并入各平台详情；总览只有心跳 + 卡片 + 日历。导航从 4 个标签变为：**总览 / 账号 / 设置** 三个常驻标签 + 平台详情推入视图。

## 4. 内容形态自适应（平台 × 形态矩阵）

表单不是写死的，全部从 `PLATFORMS` 能力表推导，服务端校验仍是唯一真值：

| 平台 | 图文 note | 视频 video | 文章 article | 字段差异 |
|---|---|---|---|---|
| 抖音 | ✅ 多图 | ✅ 单视频 | ✗ 不显示 | 定时 `YYYY-MM-DD HH:MM` |
| 小红书 | ✅ 多图 | ✅ 单视频 | ✗ 不显示 | 可见范围、原创声明（仅图文）；标题 ≤20 字；正文 >1000 字警告；定时 1h~14d |
| 视频号 | ✗ 不显示 | ✅ 单视频 | ✗ 不显示 | 未验收前与抖音同构；验收后按实测修订 |

形态切换规则（沿用并收紧 v0.2 行为）：

- 形态标签**只渲染 `spec.kinds` 里存在的项**，不出现灰色不可点的假标签；
- 媒体输入按形态收口：图文 = 多选 `image/*`；视频 = 单选 `video/*`；文章 = 单选 `.md/.txt/.html`；
- 切换形态清空媒体与定时（现有行为）；切换平台重置账号为该平台第一个已配置账号；
- 定时控件只在 `spec.scheduling !== 'none'` 时出现，格式按适配器（小红书 datetime-local → RFC3339；sau → `YYYY-MM-DD HH:MM`）；
- 标题 `maxLength`、字数警告全部读 `spec`，前端不另设限制。

## 5. 主页卡片：拖拽排序与「更多平台」

**数据模型**：新增配置字段 `homeCards: string[]`（volatile，走 DSH 原生 ConfigForms 持久化，与 `showSidebar` 同机制同通道）。语义：

- `homeCards` 是**主页显示的平台 id 顺序表**，默认 `['douyin','xiaohongshu','tencent']`（用户口述顺序，去掉未做的两个）；
- 不在 `homeCards` 里的已登记平台 = 收在「更多平台」面板里；
- 隐藏不影响任何数据：全局日历永远聚合全部平台记录，更多面板里也能进任一平台详情。

**拖拽交互**：

- 每张卡片左上角一个拖拽手柄（⠿），指针拖动 + 放置位高亮；无「保存顺序」按钮——放置即写 `homeCards`，卡片角落短暂显示「已保存」，失败则保留本地顺序并报错（复用现有错误条），刷新后以服务端为准；
- 不做键盘重排、不做编辑模式开关（避免多余按键）；拖不动的用户可在更多面板用「添加到主页」按序追加。

**「更多平台」面板**（点总览底部「+ 更多平台」展开，内联非弹窗）：

- 列出全部**有引擎背书**的已登记平台：在主页的显示「已在主页 · 移除」；不在的显示状态（可用 / 上游限制原因）+「添加到主页」；
- 「移除」只把平台从 `homeCards` 挪回面板，不删账号、不清台账；
- 面板里不出现任何无引擎平台——没有的东西不显示（2026-10-24 决策）。

## 7. 日历与数据中心落位

- **全局日历**（总览）：月历，日期格内按平台色点（小红书红、抖音黑、视频号橙…），角标数字为当日条数；点日期 → 下方过滤列表（跨平台）；平台图例可点选只看某平台；
- **平台日历**（平台详情）：同组件单平台模式，无平台色区分，只有状态色（绿=已核实发布、紫=平台已排期、橙=结果待核实、红=执行异常、蓝=已提交·待核实）；
- **数据中心**（仅平台详情内，仅小红书）：指标四格 + 近 7/30 日趋势条图 + 未关联笔记的绑定入口。sau 系平台该区域显示一行说明：「该平台上游无数据接口，暂不支持统计」——这是真话，不是省事。

数据源与协议（沿上稿不变，仅列结论）：台账零改动即可支撑日历与卡片计数；小红书数据回采新增 `metrics.json` 独立存储（快照上限 30 条/笔记）、台账可选字段 `noteRef`/`matchMethod`、四个只读+绑定精确路由（`metrics.list / metrics.refresh / notes.list / metrics.bind|unbind`）。**发布回执没有作品 ID**，匹配策略维持：标题一致 + 时间窗口自动匹配（宁可不匹配），人工绑定兜底，可解绑重绑。

## 10. 明确不做的事

- **公众号、X**（2026-10-24 决策）：无上游引擎，不注册占位、不放空卡、不评估虚工；
- 不做云端托管、团队协作、跨设备同步（本地架构不承诺）；
- 不做自动重发、不在日历/统计里嵌发布动作（可视化只读不变式不变）；
- 不引入拖拽库新依赖（Pointer Events 自实现，避免包体膨胀）；
- 设置项、4 个聊天工具、审批/确认/台账/配额语义全部保持 v0.2 原样。
